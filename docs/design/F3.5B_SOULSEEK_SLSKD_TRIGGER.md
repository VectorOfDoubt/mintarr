# F3.5b - Soulseek slskd Search/Download Trigger

> **Type:** Design document
> **Version:** 0.1 - 2026-06-01
> **Status:** Implemented
> **Related:** [F3.5_SOULSEEK_COMPLETED_INGEST.md](F3.5_SOULSEEK_COMPLETED_INGEST.md), [ADAPTER_PROTOCOL_v1.md](../specs/ADAPTER_PROTOCOL_v1.md), [HTTP_API_v1.md](../specs/HTTP_API_v1.md)

## 1. Goal

F3.5b lets Mintarr use slskd as a Soulseek download engine instead of relying
on Soularr or manual slskd UI work.

When enabled, the Soulseek adapter:

1. Searches slskd over HTTP during Mintarr Newznab searches.
2. Converts folder-level slskd search responses into `[Soulseek]` release candidates.
3. Encodes the selected slskd username/files into a Mintarr `source_id`.
4. Queues those files in slskd when Lidarr grabs the candidate.
5. Waits for files to appear in `SOULSEEK_DOWNLOAD_ROOT`.
6. Copies the completed files into Mintarr's normal pipeline.

After that, the existing normalize, verification and Lidarr ManualImport phases
run unchanged.

## 2. Non-Goals

- No replacement for Lidarr release matching.
- No automatic wanted-list scheduler inside Mintarr.
- No source deletion, consume markers or slskd cleanup.
- No peer reputation database.
- No source-specific verification thresholds.

## 3. slskd API Surface

The implementation uses the existing slskd v0 API:

- `POST /api/v0/searches` - start a search.
- `GET /api/v0/searches/{id}` and `/responses` - read search responses.
- `POST /api/v0/transfers/downloads/{username}` - queue selected files.
- `GET /api/v0/transfers/downloads/{username}` - inspect failures while waiting.

Mintarr authenticates with `X-API-Key`.

## 4. Configuration

| Env var | Default | Meaning |
|---|---|---|
| `SOULSEEK_SEARCH_ENABLED` | `false` | Enables slskd-backed search candidates. |
| `SLSKD_API_URL` | unset | Base URL of slskd, e.g. `http://host.docker.internal:5030`. |
| `SLSKD_API_KEY` | unset | slskd API key. |
| `SOULSEEK_SEARCH_TIMEOUT` | `8` | slskd search timeout, seconds; minimum `5`. |
| `SOULSEEK_SEARCH_RESPONSE_LIMIT` | `5` | Max folder-level candidates returned per query. |
| `SOULSEEK_SEARCH_FILE_LIMIT` | `500` | Max raw slskd file hits accepted per search. |
| `SOULSEEK_MIN_TRACKS` | `2` | Minimum audio files required for a folder candidate. |
| `SOULSEEK_DOWNLOAD_TIMEOUT` | `3600` | Max seconds to wait for slskd files after queueing. |
| `SOULSEEK_POLL_SECONDS` | `5` | Poll interval while waiting for slskd completion. |

F3.5a completed-folder settings still apply: `SOULSEEK_ENABLED=true`,
`SOULSEEK_DOWNLOAD_ROOT`, file/byte limits, settle window, and connector mode
`import`.

## 5. Candidate Source IDs

slskd-backed candidates use:

```text
soulseek:slskd:<base64url-json>
```

The encoded JSON contains only the slskd username, selected remote filenames,
sizes, display title and original search text. It does not contain API keys.

Mintarr validates the encoded source ID before generating NZB pointers and again
when Lidarr posts the grab back to SAB-compatible `addurl`.

## 6. Safety

- Search is opt-in via `SOULSEEK_SEARCH_ENABLED=true`.
- Completed-folder ingest continues to work without slskd API config.
- The adapter copies matched files into `ctx.raw_dir`; it does not move/delete
  slskd files.
- Partial suffixes and settle-window checks still apply.
- If slskd reports rejected/errored/cancelled transfers, Mintarr surfaces that
  as a failed source grab instead of importing partial files.

## 7. Tests

Implemented coverage:

- slskd search request/response conversion into a `ReleaseCandidate`.
- slskd source ID validation.
- slskd queue + completed-file copy path.
- SAB `addurl` accepts slskd-backed Soulseek candidates and enqueues
  `soulseek_grab`.
