# F4.5 - Optional Verifier Connectors

> **Type:** Design document
> **Version:** 1.0 - 2026-06-03
> **Status:** Implemented - first optional metadata verifier represented in registry, disabled by default
> **Related:** [F4.1 Static Connector Registry](F4.1_STATIC_CONNECTOR_REGISTRY.md), [F4.3 Connector Config And Dry-Run](F4.3_CONNECTOR_CONFIG_DRY_RUN.md), [F4.4 Connector Install Guidance](F4.4_CONNECTOR_INSTALL_GUIDANCE.md), [QUALITY_STACK_ROADMAP.md](QUALITY_STACK_ROADMAP.md)

## 1. Goal

F4.5 adds the first optional verifier lane to the connector model without
changing import policy. Optional verifier connectors must be visible to
operators, configurable through the same mode model as other connectors, and
safe to leave disabled or run in `dry_run` until their evidence is trusted.

The first slice is **Picard / beets / AcoustID metadata identity**. It is a
read-only prepass lane, not an audio-quality proof.

## 2. First Lane Decision

Choose `picard_beets_acoustid` before CUETools/CTDB.

Reasons:

- It works across source lanes; CTDB is most useful once the CD-rip lane is
  wired into scoring.
- It can start as a local `beet` binary probe with optional AcoustID API-key
  awareness, so the integration is visible without adding a network runner.
- It is clearly non-blocking evidence. Metadata identity can improve review
  context, but it cannot prove that audio is lossless or that a rip is
  authentic.

CUETools/CTDB remains planned for CD-rip evidence. A CTDB no-match must not
block imports by itself.

## 3. Runtime Shape

The connector registry contains:

```text
id: picard_beets_acoustid
kind: verifier
default_enabled: false
required: false
install_profile: null
required_env: []
optional_env: [ACOUSTID_API_KEY]
docs_url: operations/CONFIGURATION.md#35-verification-policy
capabilities:
  - metadata_identity
  - read_only_prepass
  - acoustid_lookup
```

The connector does not declare a Compose profile in this slice because the
probe is local-binary based. The installed probe checks for the `beet` binary.
This is enough for the
Integrations API and dashboard to show disabled/missing/ready status and
secret-safe setup guidance.

## 4. Sensor Policy

The sensor registry contains a matching `picard_beets_acoustid` sensor:

- class: `metadata_identity`
- stage: `metadata`
- enabled: `false`
- required: `false`
- fail policy: `warn`
- applies to all current and planned source lanes

Disabled optional sensors are excluded from `ordered()` sensor execution and do
not affect `import` validation. Enabling evidence emission is a later runtime
change, not part of this slice.

## 5. Evidence Boundary

This implementation does not persist metadata evidence yet. When a runner is
added, emitted evidence must use the existing sidecar/sensor model and stay in
review context until a separate policy change promotes it.

Allowed future evidence fields:

- matched artist / album / track identity
- MusicBrainz IDs
- AcoustID match confidence
- source tool and version
- timestamp and file path relative to the work item

Disallowed behavior:

- writing tags to source or output files
- treating identity match as audio-quality proof
- blocking imports on metadata mismatch without a separate policy decision
- exposing API-key values in status payloads

## 6. Dashboard / API Behavior

`GET /dashboard/v1/connectors` exposes the connector like every other verifier.
Because it defaults to disabled, the Integrations surface shows the mode,
health, optional env var names, and setup guidance without exposing secrets.

Operators may dry-run the connector configuration before any future import-mode
use. Required hard-gate verifiers (`ffprobe`, `flac_t`, `flac_detective`) remain
the only import-blocking verifier set.

## 7. Tests

Implemented tests cover:

- the built-in optional verifier manifest
- optional verifier dry-run validation
- the disabled metadata-identity sensor definition
- existing required sensor ordering remains unchanged
