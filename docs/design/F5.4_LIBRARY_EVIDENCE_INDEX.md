# F5.4 — Library evidence index (measured existing quality)

> **Type:** Design
> **Status:** Accepted
> **Owner:** Mintarr maintainers
> **Related:** [ADR-0008 strategic positioning](../architecture/adr/0008-strategic-positioning.md), [ADR-0012 QC import-gate scope](../architecture/adr/0012-qc-import-gate-scope.md), [Quality stack roadmap](QUALITY_STACK_ROADMAP.md), [F5.3 CD-rip evidence lane](F5.3_CD_RIP_EVIDENCE_LANE.md), [F5.4 integrity classification](F5.4_INTEGRITY_CLASSIFICATION.md), [F5.4 scan tiers](F5.4_SCAN_TIERS.md)

## 1. Problem

Today an import decision compares the **candidate's measured evidence** (ffprobe
codec gate, `flac -t`, FLAC Detective spectral) against the **existing library's
Lidarr quality *label*** — not against the existing files themselves (the
existing-quality lookup in `app/server.py` reads Lidarr trackfile labels). Two
consequences:

1. **Label trust.** If the library holds a mislabeled "FLAC" that is actually a
   transcode, Mintarr compares the candidate against that lie (1411/3000 kbps)
   and can block a genuine upgrade — or accept a worse one.
2. **No lossless-tier resolution.** `new_effective_kbps` is a flat 3000 for any
   real FLAC, so 16/44 vs 24/96 is invisible to the decision even though ffprobe
   already captured bit depth / sample rate.

The asymmetry is the root issue: the new file is *measured*, the existing file
is *assumed*. "Quality first" requires measuring both with the same tools.

## 2. Decision

Mintarr maintains a **read-only library evidence index**: it measures existing
library files with the **same sensor model** as the import flow and stores the
results in `state_db`. Import decisions then compare two like-for-like objects —
`candidate_import_evidence` vs `existing_library_evidence` — instead of
candidate-evidence vs Lidarr-label.

**Lidarr stays the truth for identity/ownership** (which artist/album/track, and
which trackfiles exist). **Mintarr becomes the truth for audio quality.** This
extends [ADR-0008](../architecture/adr/0008-strategic-positioning.md) (Mintarr
as the QC + import-orchestration layer) to "…and a read-only quality register
over the library." It stays within ADR-0008's boundaries: **read-only** — no tag
writing, no re-encoding, no library reorganization. *(Open question §8: this
positioning shift may warrant an ADR amendment.)*

## 3. Architecture

Two evidence objects, one sensor model:

```
existing_library_evidence  (measured from the on-disk library file)
candidate_import_evidence  (measured from the incoming candidate — already exists)
        │                                  │
        └──────────────┬───────────────────┘
                       ▼
         decision: candidate vs measured existing
```

Reuse the existing sensor results contract (ffprobe, `flac_t`, `flac_detective`,
`release_identity`, and later DR/loudness/AcoustID). The same `SensorResult`
shape and `evidence_schema_version` apply, so library evidence is queryable and
auditable exactly like import evidence.

### 3.1 Cost is the hard constraint — tiered scanning

FLAC Detective is the heaviest sensor (minutes/album). A full-library *eager*
spectral scan does not scale. The index is therefore **tiered**:

| Tier | Sensors | Cost | When |
|---|---|---|---|
| Cheap | ffprobe (codec, bitrate, sample rate, bit depth, channels) | sub-second/file | eager / on first sight |
| Integrity | `flac -t` | seconds/album | lazy or background-throttled |
| Spectral | FLAC Detective | minutes/album | **on-demand** (a candidate targets this album) or background-throttled, never full-library-eager |

### 3.2 Lead with on-demand, not a full batch

The import decision only needs measured evidence for the **album the candidate
targets**. Mintarr already fetches that album's trackfile paths from Lidarr, so
the smallest correct fix is: at import time, measure the existing files for
*that album* on demand, cache the result in the index, and compare. This closes
the correctness gap with no library-wide batch job. The **background full-library
index + ranking dashboard** is a superset that follows (slice 5+).

### 3.3 File-access contract (locked for slice 1)

Measuring existing files requires Mintarr to **read** the library; today it only
mounts `OUTPUT_BASE`. The contract:

| Env | Meaning |
|---|---|
| `MINTARR_LIBRARY_ROOT` | Mintarr's **read-only** mount of the Lidarr library root (unset ⇒ measurement off, label-only fallback) |
| `MINTARR_LIBRARY_LIDARR_ROOT` | Lidarr's view of that same root — the path prefix that appears in trackfile `path` |

**Mapping.** For a Lidarr trackfile `path`, strip the `MINTARR_LIBRARY_LIDARR_ROOT`
prefix and join the remainder onto `MINTARR_LIBRARY_ROOT`. A `path` that does not
start with the configured Lidarr root is **unmapped** (fallback, not an error).

**Containment + safety (reuse the restore/backup discipline).**

- Resolve the mapped path with `realpath` and require it to stay
  `is_relative_to(MINTARR_LIBRARY_ROOT)` — reject traversal and symlink escape.
- Reject symlinked files (or resolve and re-check containment); never follow a
  link out of the mount.
- Open **read-only**; never write/move/delete/rename inside the library.

**Fallback (never crash, never block).** If `MINTARR_LIBRARY_ROOT` is unset, the
path is unmapped/unresolvable/missing, or fails containment, that trackfile is
recorded as `unmeasured` with a reason and the album falls back to today's
Lidarr-label behaviour.

### 3.4 Storage + staleness

A new `library_evidence` table in `state_db`, keyed by Lidarr `trackfile_id`,
storing: album id, resolved path, `size`, `mtime`, the per-sensor results, the
measured **quality vector** (§4), `sensor_version`, and `measured_at`. Evidence
is **re-measured when `(path, size, mtime)` changes** (Lidarr replaced the file)
and invalidated when Lidarr reports the trackfile gone. `sensor_version` is
stored so historical measurements stay interpretable (same audit principle as
decisions).

## 4. Quality vector + precedence (not just "better kbps")

Quality is a **vector**, not a scalar bitrate. Each track's measured evidence
yields the dimensions below; comparison is **lexicographic by precedence**, so a
higher tier never excuses a failure on a more important axis:

| # | Axis | Source | Rule |
|---|---|---|---|
| 1 | **Identity** | F5.1 release identity | `WRONG_ALBUM` is disqualifying — quality can never override the wrong release (ADR-0013). |
| 2 | **Hard validity** | ffprobe + `flac -t` | A file that doesn't decode / fails integrity is unusable regardless of nominal format. |
| 3 | **Authenticity** | FLAC Detective | A measured-fake "FLAC" loses to a genuine one at the same nominal format. |
| 4 | **Lossless tier** | ffprobe codec / bit depth / sample rate | lossless > lossy; among lossless, higher bit depth / sample rate is better. |
| 5 | **Completeness** | Lidarr track stats | More complete is better; may override a *tier* gap (§5) since a complete release beats a partial one. |

Comparison: a candidate **replaces** the existing release only when it is at
least equal on every higher-precedence axis and strictly better on one, or it
resolves a defect the existing release has (invalid/fake/incomplete). Otherwise
the existing release is kept, or — when the comparison is genuinely close or
mixed — routed to `REVIEW_REQUIRED` so the operator keeps the veto. The result
maps onto the existing `ACCEPT` / `ACCEPT_PROVISIONAL` / `REVIEW_REQUIRED` /
`BLOCK` decisions and keeps ADR-0013 two-axis precedence.

### 4.1 Default-safe rollout

Gated by `MINTARR_MEASURED_EXISTING` (default **off** ⇒ today's label
behaviour), and only when measured existing evidence is available; otherwise it
falls back to the label path. So the change cannot regress decisions until opted
in, and an unmeasured/unmounted library behaves exactly as today.

## 5. Album / release rollup

Evidence is stored per `trackfile_id`, but the import decision is at
**album/release** level. Roll the per-track vectors up as follows:

- **Validity:** the album is valid only if **every present track** passes hard
  validity; any invalid track is an album-level integrity defect (a candidate
  that fixes it can win).
- **Authenticity:** album authenticity = the **worst** track (one fake track
  taints the release's authenticity claim) — but per-track evidence is retained,
  and "one bad track" surfaces the release as `SUSPICIOUS` → `REVIEW_REQUIRED`,
  never a silent accept.
- **Lossless tier:** album tier = the **minimum** tier across tracks; a
  mixed-quality album is explicitly flagged (not averaged into looking better
  than its weakest track).
- **Completeness:** present vs `expected_track_count` (Lidarr); multi-disc uses
  Lidarr's aggregate track counts across discs.
- **"One bad track" rule:** an otherwise-equal candidate that fixes a single
  invalid/fake/missing track in the existing release wins; a candidate that
  *introduces* a single fake/invalid track among good ones → `REVIEW_REQUIRED`.

Per-track replacement (swapping one file) is **out of scope for v1** — Mintarr
decides at the release granularity it already imports at.

## 6. Dashboard visibility

Surface `existing_library_evidence` in the record drawer (and later a library
view): the operator must see *why* Mintarr judges the existing file good/bad —
measured codec/bit depth/sample rate/spectral verdict, not a bare label.

## 7. Non-goals

- No tag writing, no re-encoding, no library reorganization — read-only
  ([ADR-0008](../architecture/adr/0008-strategic-positioning.md) boundary).
- No replacing Lidarr as identity/ownership truth.
- Not a general music-analysis service; evidence exists to inform Mintarr
  decisions and operator review.
- No full-library eager spectral scan.

## 8. Implementation slices

1. **On-demand existing-album measurement (pure + cached).** Resolve the target
   album's trackfile paths (Lidarr) → Mintarr mount; measure with ffprobe (+
   `flac -t`); store in `library_evidence`. Graceful degrade if unmounted. **No
   decision change** — evidence recorded only.
2. **Dashboard visibility.** Show measured existing evidence in the record drawer.
3. **Decision uses measured existing (flag-gated).** `MINTARR_MEASURED_EXISTING`
   default-off: compare candidate vs measured existing, incl. lossless tiers.
4. **Spectral tier on-demand.** Add FLAC Detective to the existing-album
   measurement (throttled) so measured-fake existing FLAC is detectable.
5. **Background full-library index + ranking.** Tiered, throttled scan of the
   whole library; library quality view; re-scan on change. (Largest slice; see
   §8c.)

## 8b. Spectral existing measurement (slice 4 detail)

Slices 1–3 measure the existing library's **codec / integrity / lossless tier**
but not its **authenticity** — so a measured-fake "FLAC" (an upsampled or
transcoded file) in the library still reads as a clean high tier, and a genuine
real-lossless candidate could be wrongly judged a downgrade against it. Slice 4
closes that by running FLAC Detective on the existing files too. It is the
heaviest tier, so it is designed for cost.

- **Separate opt-in flag.** `MINTARR_LIBRARY_SPECTRAL` (default-off), *in addition
  to* `MINTARR_MEASURED_EXISTING`. Operators accept the extra per-import cost
  explicitly; the cheap ffprobe/`flac -t` tier stays the default.
- **On-demand + freshness-cached.** Only the targeted album's existing files are
  analysed, and only when the stored spectral evidence is stale (same
  path/size/mtime/sensor-version basis as §3.4). Re-imports of an unchanged album
  pay nothing. Never full-library-eager (that is slice 5).
- **Deployment requirement.** FLAC Detective reads files at a path, so its
  container must also mount the library (read-only) at the same path Mintarr
  resolves (`MINTARR_LIBRARY_ROOT`). If Detective cannot read the file, the
  spectral result is **unknown** (not "authentic") — see below.
- **Authenticity is a tri-state, not a boolean.** Store the Detective verdict +
  an `authentic` value that is `True` / `False` / **unknown** (not spectrally
  measured or Detective unreachable). The rollup (§5) gains `any_fake` and
  `authenticity_known`; **unknown existing authenticity must not be read as
  authentic.**
- **Comparison (extends §4).** Authenticity outranks tier (already true for the
  candidate). On the existing side: if `existing.any_fake` and the candidate is
  authentic → `UPGRADE` (a real lossless beats a measured-fake hi-res, even at a
  lower nominal tier). If existing authenticity is **unknown** and the decision
  would hinge on tier alone, prefer `REVIEW` over silently trusting the existing
  file — symmetric with the candidate unknown-tier abstain. The unknown-abstain
  rests on one asymmetry: **unknown existing authenticity can only inflate the
  existing tier (an upsampled fake reports hi-res), never deflate it.** So an
  `UPGRADE` verdict (candidate strictly higher tier, or a completeness upgrade at
  equal tier) is always safe and is emitted as-is; only the `DOWNGRADE` /
  `EQUIVALENT` outcomes — which *trust* the existing tier — abstain to `REVIEW`.
- **Never blocks on its own / default-safe.** Same guarantees as slice 3b:
  subordinate to identity, never overrides a hard-gate `BLOCK`, falls back to the
  label/cheaper-tier path when spectral evidence is unavailable.

### 8b.1 Analysis scope & mechanism — locked

The unit of analysis is the **individual trackfile, never a directory**. Detective
is invoked once per existing `trackfile_id`, against the *exact* path that §3.3
already resolved and containment-checked for that trackfile — not its parent
folder, not a glob. This is deliberate over the "point Detective at the album
directory and filter the results" alternative, which is unsafe here:

- **No path comes from the filesystem.** Every analysed path is a Lidarr
  trackfile path, prefix-mapped and realpath-contained per §3.3. Mintarr never
  enumerates a directory to discover files, so stray, foreign, or stale files
  sharing the album folder (extras, other releases, deleted-but-present files,
  symlinks) can never be measured or cached.
- **Results are keyed by `trackfile_id`, not by basename or directory.** A
  spectral verdict is stored only against the trackfile it was produced for. If a
  returned result cannot be matched back to a known trackfile path in the album's
  trackfile set (e.g. Detective batched a folder), it is **discarded, not cached**
  — there is no "nearest filename" or directory-rollup matching.
- **Rollup uses only the album's own trackfiles.** `any_fake` /
  `authenticity_known` (§5 extension) aggregate exclusively over the
  `library_evidence` rows for *this album's* `trackfile_id`s. A file outside that
  set cannot influence the album's authenticity even if it lives in the same
  directory.
- **Freshness is per-trackfile** (same path/size/mtime/sensor-version basis as
  §3.4): one changed file re-measures only itself, never the folder.

In short: per-trackfile in, per-`trackfile_id` out, exact-path matched, unmatched
results dropped. Directory- or staging-level analysis is explicitly rejected
because it risks caching another file's authenticity against this album.

Sub-slices: (4a) store the spectral verdict in `library_evidence` + roll
authenticity up (record-only); (4b) wire existing authenticity into `compare()`
behind the flag.

**Status — slices 4a + 4b shipped (opt-in).** Behind `MINTARR_LIBRARY_SPECTRAL`
(default-off), the record-loop measures each existing trackfile's authenticity
per §8b.1 and stores the tri-state verdict on its `library_evidence` row
(separate `spectral_sensor_version` + freshness, so the cheap ffprobe tier is
never clobbered or re-run). `album_quality` rolls it up to `any_fake` /
`authenticity_known`, surfaced in the drawer (4a).

With `MINTARR_MEASURED_EXISTING` *also* on, `compare()` reads the existing
authenticity (4b): `any_fake` → `UPGRADE` above the tier comparison, and an
unverified existing tier abstains to `REVIEW` on the keep/downgrade outcomes. The
authenticity read is gated on `consider_existing_authenticity=spectral_enabled()`
so that with the spectral tier off — where `authenticity_known` is False for
every album — no decision is ever routed to review for missing authenticity. It
stays default-safe: subordinate to identity, never overrides a hard-gate `BLOCK`,
and an `UPGRADE` only ever lifts a `REVIEW_REQUIRED` to `ACCEPT_PROVISIONAL`.

The spectral verdict has its *own* decision-time freshness, independent of the
cheap tier (the same boundary the cheap tier holds): at decision time a row whose
spectral evidence fails `is_spectral_row_fresh` (changed file, older spectral
sensor version, or never re-run) has its authenticity stripped, so a stale
`authentic=0/1` can never drive a verdict — the row keeps its fresh cheap-tier
tier/validity and simply reads as unverified authenticity.

## 8c. Background full-library index (slice 5 detail)

Slice 1–4 are **targeted**: Mintarr measures the album a candidate is about to
replace. Slice 5 adds a library-wide quality register and ranking view, but it
must not weaken Mintarr's primary job as the pre-Lidarr QC gate. The background
index therefore has one rule above all others:

> **Import-time QC always wins.** A background scan is low-priority, resumable,
> cancelable work. It must never starve the import worker, FLAC Detective, or
> operator review paths.

### 8c.1 Trigger model

Do **not** run a full scan automatically just because Mintarr starts or the
library mount appears. Large libraries can be tens of thousands of files; a
surprise first boot scan would compete with imports and external tools.

Triggers are deliberately staged:

| Trigger | Default | Scope | Notes |
|---|---|---|---|
| **Operator-started scan** | enabled | cheap/integrity tier first | MVP. The operator explicitly starts, pauses, resumes, or cancels the scan from the dashboard/API. |
| **Import-time on-demand measurement** | existing behaviour | target album only | Remains the decision path; it may pre-empt or run ahead of the background scan. |
| **Scheduled scan** | off | cheap/integrity tier | Follow-up. `MINTARR_LIBRARY_SCAN_INTERVAL_HOURS=0` means disabled. Never starts if an import is active. |
| **On-connect scan** | off / rejected for v1 | none | Too surprising and too expensive. A future "library mounted; N unmeasured files" discovery banner is acceptable. |
| **Background spectral scan** | off, separate opt-in | limited batches | Never part of the default full-library scan. See §8c.4. |

The MVP is operator-started cheap/integrity scanning plus a ranking view. That
delivers the product value (know what quality is on disk) without creating hidden
load.

### 8c.2 Work model and state

The scanner snapshots Lidarr's current trackfile list, then processes work at
`trackfile_id` granularity — the same unit as the evidence table:

1. Fetch artists/albums/trackfiles from Lidarr using existing read-only API
   patterns. Lidarr remains identity/ownership truth.
2. For each trackfile, resolve the library path via §3.3.
3. If `(path, size, mtime, sensor_version)` is fresh, skip.
4. Otherwise run the cheap/integrity measurement and upsert `library_evidence`.
5. Record per-item outcome (`measured`, `fresh`, `unmapped`, `missing`, `error`)
   without failing the whole scan.

Add scan-run state in `state_db` rather than in process memory:

| Table / field | Purpose |
|---|---|
| `library_scan_runs` | one row per scan: id, mode, state, started_at, finished_at, totals, cancel flag, last_error |
| `library_scan_items` | item ledger for resume/progress: run_id, trackfile_id, album_id, state, attempts, last_error |
| F2 `jobs` row | the actual scanner lease: heartbeat, lease expiry, cancel flag, priority, dedupe key |

Do **not** create a second scan-specific lease table. The F2 queue already owns
lease, heartbeat, cancellation, priority, stale recovery, and active-job dedupe.
A scan run is backed by a low-priority `library_scan` job with a stable
`dedupe_key`, while `library_scan_runs` and `library_scan_items` store
scan-specific progress. This prevents duplicate scanners under multi-worker or
restart scenarios without reimplementing queue semantics. A crashed process
leaves an expired F2 lease and a resumable scan run, never concurrent writes.

### 8c.3 Throttle and priority budget

Background scanning is I/O and subprocess-heavy (`ffprobe`, `flac -t`, and
optionally FLAC Detective). The budget is intentionally conservative:

- **One background scan worker** per Mintarr instance.
- **One trackfile at a time** in v1. Parallelism can be added after metrics show
  the cost profile; correctness does not require it.
- **Pause before each item** if an import/promotion/verification job is active
  or queued. Import-time QC may measure its target album immediately; the
  background scan waits.
- **Small sleeps / yield points** between items so cancel/pause is responsive.
- **Hard per-tool timeouts** reuse the existing measurement timeouts. A timeout
  marks that item `error`/`unmeasured`, not the scan failed.
- **No shared FLAC Detective pressure** by default. Spectral batch scanning is a
  separate mode (§8c.4), not part of cheap scan.

This means the first implementation can be simple and predictable: slow is fine;
starving imports is not.

### 8c.4 Spectral in the background

Full-library FLAC Detective is the expensive tier. Treat it as a different
operation from cheap indexing:

- Default-off even when `MINTARR_LIBRARY_SPECTRAL=true`; that flag enables
  **on-demand** spectral measurement for target albums, not automatic background
  Detective over the whole library. Background spectral additionally requires
  `MINTARR_LIBRARY_BACKGROUND_SPECTRAL=true`.
- Background spectral is an explicit `mode=spectral_missing` scan.
- Only scan trackfiles whose cheap evidence is fresh and whose spectral evidence
  is absent/stale.
- Maintain one-Detective-request-at-a-time and pause for imports.
- The worker pauses before each Detective request. If import work arrives after a
  request has already started, v1 lets that one file finish before yielding
  again; no further background Detective requests are started while import work
  is active.
- Surface ETA/cost plainly in the UI before the operator starts it.

The product goal is to identify fake existing FLACs, but not at the cost of
making Mintarr unusable while the library is being analyzed.

### 8c.5 Ranking view

The ranking view is a **quality register**, not a wanted/missing manager. It
derives from `library_evidence` and Lidarr identity only:

| Rank bucket | Meaning |
|---|---|
| `invalid` | one or more measured tracks fail integrity / decode |
| `measured_fake` | one or more spectrally measured tracks are fake |
| `checksum_mismatch` | decodes fine, but the stored FLAC MD5 is stale (re-tagged after ripping) |
| `lossy` | one or more tracks are lossy (tier 0) — an actionable lossless upgrade |
| `redbook` | all lossless but the weakest track is CD tier (16/44) — fine, not a defect |
| `mixed_tier` | all lossless hi-res, but tracks roll up to different tiers |
| `integrity_unknown` | metadata measured (tier known) but `flac -t` integrity not verified yet — not a defect, and never shown as `ok` |
| `unknown_authenticity` | cheap evidence exists but spectral authenticity is unknown |
| `unmeasured` | trackfiles exist but no usable measurement is available |
| `stale` | stored evidence exists but no longer matches path/size/mtime/version |

It may show artist/album names from Lidarr and **basenames only** for files. It
must not expose mount paths, API keys, or download URLs. It must not create a
wanted list, mutate Lidarr, or enqueue downloads by itself; any future "search
for upgrade" action would be a separate opt-in workflow and ADR review.

### 8c.6 API and dashboard shape

The implementation should expose small, explicit controls:

| Endpoint / UI | Behaviour |
|---|---|
| `POST /library/scan` | start an operator-triggered scan (`mode=cheap` first) |
| `GET /library/scan` | current/last scan status and progress |
| `POST /library/scan/cancel` | request cancellation; worker stops at next yield point |
| `GET /dashboard/v1/library-quality` | paginated rank buckets and rollups |

All endpoints are authenticated. A scan start returns `409` if another scan lease
is active. Cancel is best-effort and idempotent. The dashboard should show
progress, current mode, last error summary, and clear "imports take priority"
wording.

### 8c.7 Failure semantics

- Lidarr API unavailable: scan run becomes `failed` or `paused`, depending on
  whether it had already started processing; import-time fallback remains label
  mode.
- Library unmounted / path unmapped: per-track `unmeasured`, not scan failure.
- Tool failure: per-track `error` with reason, scan continues.
- Process crash / restart mid-scan: boot recovery fails the backing F2 job, but
  the `library_scan_runs` row is left active (`running`/`cancelling`). On
  scan-worker startup, `reconcile_orphaned_library_scan_runs` marks any active run
  whose job is terminal or missing as `failed`, so the orphan cannot block future
  scans via the active-run dedupe. A run whose job is still `queued`/`running` is
  left for the live worker. The operator then starts a fresh scan; freshness +
  `sensor_version` checks make already-measured items cheap to re-confirm.
- Schema/version change: old evidence is treated as stale by the existing
  `sensor_version` checks and re-measured lazily.

### 8c.8 Slice 5 implementation plan

1. **5a — design + docs.** Lock trigger/throttle/lease/ranking model. No code.
2. **5b — scan state + F2 job binding.** Add `state_db` scan-run/item tables,
   enqueue a low-priority `library_scan` job for the F2 lease/cancel/dedupe
   primitive, and cover it with pure tests. No scanner/executor yet.
3. **5c — operator-started cheap scan worker.** One worker, one file at a time,
   reusing `measure_trackfile`; authenticated start/status/cancel endpoints.
4. **5d — dashboard ranking view.** Read-only library quality buckets and scan
   progress. No decisions change.
5. **5e — scheduled cheap scan.** Default-off interval, lease-aware, never starts
   while imports are active.
6. **5f — background spectral batch.** Separate opt-in `spectral_missing` mode,
   cheap-fresh prefilter, item-ledger resume/skip, and import-priority pause
   before each Detective request.

## 9. Decisions taken & open questions

- **ADR-0008 amendment — decided:** no full ADR is needed before slices 1–2
  (read-only measurement + visibility change nothing). Before **slice 3** (when
  measured evidence changes decisions) we land a short ADR-0008 amendment stating
  that Mintarr may hold **read-only quality evidence over Lidarr-owned files but
  does not own library management**.
- **Mount contract — locked** in §3.3 (`MINTARR_LIBRARY_ROOT` +
  `MINTARR_LIBRARY_LIDARR_ROOT`, realpath containment, symlink rejection,
  read-only, `unmeasured` fallback). Partial reachability degrades per-trackfile.
- **Quality vector + rollup — locked** in §4–§5.
- **Background scan trigger/throttle — decided for slice 5:** operator-started
  cheap/integrity scan first; scheduled scan is default-off follow-up; on-connect
  full scan is rejected for v1; background spectral is a separate opt-in mode.
  One background worker, one file at a time, lease-protected, and paused/yielded
  around import activity so the QC gate remains primary.
