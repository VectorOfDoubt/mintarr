# F4.3 - Connector Config And Dry-Run

> **Type:** Design document
> **Version:** 0.1 - 2026-06-01
> **Status:** Implemented - SQLite config, validation endpoint, dashboard controls, and source runtime gates
> **Related:** [F4.1 Static Connector Registry](F4.1_STATIC_CONNECTOR_REGISTRY.md), [F4.2 Integrations Dashboard](F4.2_INTEGRATIONS_DASHBOARD.md), [CONNECTOR_MANIFEST_v1.md](../specs/CONNECTOR_MANIFEST_v1.md), [HTTP_API_v1.md](../specs/HTTP_API_v1.md)

## 1. Goal

F4.3 turns the read-only connector registry into operator-controlled runtime config.

Operators should be able to:

- inspect each connector's configured mode
- dry-run a mode change without mutating persisted config
- persist a connector mode change
- see validation errors before a change can break imports

## 2. Modes

Connector modes use the existing `ConnectorMode` enum:

| Mode | Meaning |
|---|---|
| `disabled` | Connector is operator-disabled and should not participate in runtime workflows. |
| `dry_run` | Connector is enabled for health/config inspection only. Source and output connectors do not perform imports in this mode. |
| `import` | Connector may participate in runtime import workflows if installed and healthy. |

`enabled` remains a convenience boolean in API payloads. It is derived from mode:

- `disabled` -> `enabled=false`
- `dry_run` / `import` -> `enabled=true`

## 3. Persistence

Add a `connector_config` table to the existing SQLite state DB:

```sql
CREATE TABLE IF NOT EXISTS connector_config (
    connector_id TEXT PRIMARY KEY,
    enabled INTEGER NOT NULL,
    mode TEXT NOT NULL,
    updated_at REAL NOT NULL,
    actor TEXT
);
```

No secrets are stored. Config rows contain connector IDs, booleans, modes, timestamps, and actor labels only.

If no row exists, runtime falls back to `manifest.default_enabled`:

- `true` -> `import`
- `false` -> `disabled`

## 4. Validation

Mutation validates against the full proposed registry state:

1. Unknown connector IDs return `404`.
2. Unknown modes return `400`.
3. Required connectors cannot be disabled or moved out of `import`.
4. If any installed source connector is in `import`, every required verifier must be installed and in `import`.
5. If any installed source connector is in `import`, at least one output connector must be installed and in `import`.

Dry-run requests run the same validation but do not persist.

## 5. Runtime Enforcement

F4.3 should not only change dashboard display. Runtime entry points must respect source mode:

- Newznab search only includes source adapters whose connector mode is `import`.
- SAB `addurl` rejects source grabs when the source connector is not in `import`.
- NZB download endpoints reject disabled/dry-run sources.
- Local ingest rejects disabled/dry-run local source mode.

Verifier and output modes are enforced by mutation validation in this slice. Deeper pipeline-level output routing remains future work.

## 6. HTTP API

Add:

```text
POST /dashboard/v1/connectors/<connector_id>/config
```

Request:

```json
{
  "mode": "dry_run",
  "dry_run": true
}
```

Response:

```json
{
  "connector_id": "tidal",
  "dry_run": true,
  "valid": true,
  "config": {
    "connector_id": "tidal",
    "enabled": true,
    "mode": "dry_run",
    "updated_at": null,
    "actor": "user_dashboard"
  },
  "errors": []
}
```

For persisted changes, `dry_run=false` and `updated_at` is populated.

## 7. Dashboard UI

The Integrations tab adds a compact mode selector per connector with:

- current mode
- dry-run validation action
- apply action
- inline validation result via existing toast feedback

The UI displays env var names only. No env values, tokens, API keys, or credentials are exposed.
