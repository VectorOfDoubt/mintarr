# F5.4 — Integrity classification (decode errors vs advisory cleanup findings)

> **Type:** Design
> **Status:** Accepted
> **Owner:** Mintarr maintainers
> **Related:** [F5.4 library evidence index](F5.4_LIBRARY_EVIDENCE_INDEX.md), [ADR-0008 strategic positioning](../architecture/adr/0008-strategic-positioning.md)

## 1. Problem (found in dogfood)

The first at-scale library scans (≈46k trackfiles) surfaced two distinct classes
that `flac -t` reported as non-zero:

1. **Stale FLAC MD5.** The audio decodes, but STREAMINFO MD5 no longer matches
   after re-tagging or re-processing. This is playable audio, not corruption.
2. **ID3-contaminated FLAC.** Dogfood later found **2942 FLAC files** across
   **146 albums** with `flac -t` `LOST_SYNC` failures and ID3 markers
   (`2930` trailing ID3v1 tags, `1070` ID3v2 headers). This is a non-standard
   FLAC/tagging violation and a cleanup candidate. It must not be treated as
   random bitrot or as an automatic replacement trigger.

Today `app/library_evidence.py:_default_prober` collapses both cases into one
bit: `integrity_ok = (flac -t returncode == 0)`. So an MD5 mismatch is recorded
identically to genuine decode corruption. ID3-contaminated FLAC would do the
same. Via the rollup, `existing.any_invalid` is True, and
`library_comparison.compare()` returns `UPGRADE`. **If
`MINTARR_MEASURED_EXISTING` were enabled, Mintarr would recommend re-downloading
playable/repairable files** purely because they carry stale or non-standard
metadata — the opposite of "quality truth."

## 2. Decision

Split the FLAC integrity signal into two independent dimensions:

| Dimension | Meaning | `flac -t` evidence |
|---|---|---|
| **Decode validity** (`integrity_ok`) | The audio frames decode; the file is usable | non-zero **only** on real decode/frame errors |
| **Checksum verification** (`checksum_ok`) | The decoded audio matches the stored STREAMINFO MD5 | `False` on `MD5 signature mismatch`; `True` when verified; `None` when not applicable/unchecked |
| **Integrity issue** (`integrity_issue`) | Advisory classifier for non-corruption findings | `checksum_mismatch`, `nonstandard_flac_tags`, `decode_corrupt`, or `NULL` |

An **MD5 mismatch becomes `integrity_ok=True, checksum_ok=False`** — the file is
valid, usable audio with a stale checksum. An **ID3-contaminated FLAC becomes
`integrity_ok=NULL, checksum_ok=NULL, integrity_issue=nonstandard_flac_tags`** —
cleanup/advisory, not a replacement trigger. A **hard decode error stays
`integrity_ok=False, integrity_issue=decode_corrupt`** (genuine corruption),
exactly as today.

### 2.1 Distinguishing the two from `flac -t`

`flac -t` returns non-zero for both, so classify by stderr:

- stderr contains **`MD5 signature mismatch`** (case-insensitive) and shows no
  decode/frame error → **checksum mismatch** (`integrity_ok=True`,
  `checksum_ok=False`, `integrity_issue=checksum_mismatch`).
- stderr contains ID3 markers (`ID3v1 tag`, `ID3v2 tag`) plus sync/end-of-stream
  decode errors → **non-standard FLAC tags** (`integrity_ok=NULL`,
  `checksum_ok=NULL`, `integrity_issue=nonstandard_flac_tags`).
- any other non-zero result (decode errors, frame CRC errors, truncation,
  unreadable) → **hard error** (`integrity_ok=False`). This is the
  **conservative default**: an unrecognized `flac -t` failure is treated as
  invalid, never softened.
- returncode 0 → `integrity_ok=True`, `checksum_ok=True` (flac verified the MD5;
  an *unset* STREAMINFO MD5 also exits 0 and is reported `checksum_ok=None`,
  since nothing was checked — see §3).

Non-FLAC codecs (where `flac -t` does not run) keep `checksum_ok=None`.

## 3. Data model

`TrackMeasurement` (in `library_evidence.py`) has `checksum_ok: bool | None` and
`integrity_issue: str | None`. `library_evidence` has nullable `checksum_ok
INTEGER` and `integrity_issue TEXT` columns (idempotent migrations, same pattern
as the spectral columns). Old rows read `NULL` until re-measured.

`INTEGRITY_SENSOR_VERSION` is **bumped** when the classifier changes: the
meaning of `integrity_ok` changes (MD5 mismatch flips `False → True`; ID3-tagged
FLAC flips `False → NULL + nonstandard_flac_tags`), so every stored integrity row
must be re-measured under the new semantics. The existing integrity freshness
guard makes the next integrity scan re-measure all rows automatically; no
backfill script is needed.

## 4. Rollup + comparison

`AlbumQuality` (in `library_comparison.py`) exposes advisory flags:
`any_md5_mismatch` and `any_nonstandard_flac_tags`. `album_quality` keeps
`any_invalid` meaning **decode-invalid only** (now strictly genuine corruption).

`compare()` is **unchanged in behaviour** and deliberately does **not** act on
`any_md5_mismatch` or `any_nonstandard_flac_tags`: neither is a quality defect
that should automatically replace the existing release. Both are **advisory
only** — surfaced in the ranking, invisible to the replacement decision.

## 5. Ranking view

Add advisory buckets to the library-quality ranking. Worst-first precedence:

```
invalid → nonstandard_flac_tags → measured_fake → checksum_mismatch → stale
→ unmeasured → lossy → redbook → mixed_tier → integrity_unknown
→ unknown_authenticity → ok
```

Labels make the distinction explicit:

- `invalid`: hard decode corruption.
- `nonstandard_flac_tags`: FLAC carries ID3 tags; cleanup candidate, not a
  replacement trigger.
- `checksum_mismatch`: plays fine; stored FLAC MD5 no longer matches the audio.

The ranking is DB-only (no live stat, per the slice-5d contract). Bucket counts
must aggregate over **all** `library_evidence` rows, not the first page/cap of
rows.

## 6. Default-safety & scope

- Scoped to `library_evidence` measurement of **existing** files. The import
  candidate's hard gates are unchanged.
- No decision changes when `MINTARR_MEASURED_EXISTING` is off (default).
- Conservative: only explicit, known advisory patterns are softened; every other
  `flac -t` failure stays `invalid`.
- Read-only throughout; no file is modified, and Mintarr never rewrites a FLAC
  MD5 or strips ID3 tags (that would be library management, outside ADR-0008).

## 7. Test plan

- Prober classification (injected fake `flac -t` results): clean → ok/checksum_ok
  True; `MD5 signature mismatch` → integrity_ok True + checksum_ok False;
  ID3+LOST_SYNC → nonstandard_flac_tags; decode error → integrity_ok False;
  unset-MD5 (rc 0) → checksum_ok None; non-FLAC → checksum_ok None.
- Storage round-trip of `checksum_ok` and `integrity_issue` (incl. migrations on
  a pre-existing DB).
- `album_quality`: `any_md5_mismatch` set from a fresh checksum-mismatch row;
  `any_invalid` **not** set by a checksum mismatch.
- `compare()`: a candidate vs an existing album whose only defect is an MD5
  mismatch does **not** return `UPGRADE` on that basis (no auto-replace of
  playable files).
- Ranking: checksum-mismatch and nonstandard-tag albums land in their advisory
  buckets, not `invalid` and not `ok`; precedence respected; bucket counts cover
  the full evidence table.

## 8. Non-goals

- No FLAC re-encoding, MD5 rewriting, or ID3 stripping (Mintarr stays read-only
  over the library).
- No change to spectral authenticity, tiers, or completeness.
- No new env flag — this is a correctness fix to existing measurement, on by
  default for the measurement/ranking; it only reaches a decision when the
  existing `MINTARR_MEASURED_EXISTING` opt-in is enabled.
