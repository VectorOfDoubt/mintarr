# F5.4 — Library evidence index (measured existing quality)

> **Type:** Design
> **Status:** Proposed
> **Owner:** Mintarr maintainers
> **Related:** [ADR-0008 strategic positioning](../architecture/adr/0008-strategic-positioning.md), [ADR-0012 QC import-gate scope](../architecture/adr/0012-qc-import-gate-scope.md), [Quality stack roadmap](QUALITY_STACK_ROADMAP.md), [F5.3 CD-rip evidence lane](F5.3_CD_RIP_EVIDENCE_LANE.md)

## 1. Problem

Today an import decision compares the **candidate's measured evidence** (ffprobe
codec gate, `flac -t`, FLAC Detective spectral) against the **existing library's
Lidarr quality *label*** — not against the existing files themselves (the
existing-quality lookup in `app/server.py` reads Lidarr trackfile labels). Two
consequences:

1. **Label trust.** If the library holds a mislabeled "FLAC" that is actually a
   transcode, Mintarr compares the candidate against that lie (1411/3000 kbps)
   and can block a genuine upgrade — or accept a worse one.
2. **No lossless-tier resolution.** `new_effective_kbps` is a flat 3000 for any
   real FLAC, so 16/44 vs 24/96 is invisible to the decision even though ffprobe
   already captured bit depth / sample rate.

The asymmetry is the root issue: the new file is *measured*, the existing file
is *assumed*. "Quality first" requires measuring both with the same tools.

## 2. Decision

Mintarr maintains a **read-only library evidence index**: it measures existing
library files with the **same sensor model** as the import flow and stores the
results in `state_db`. Import decisions then compare two like-for-like objects —
`candidate_import_evidence` vs `existing_library_evidence` — instead of
candidate-evidence vs Lidarr-label.

**Lidarr stays the truth for identity/ownership** (which artist/album/track, and
which trackfiles exist). **Mintarr becomes the truth for audio quality.** This
extends [ADR-0008](../architecture/adr/0008-strategic-positioning.md) (Mintarr
as the QC + import-orchestration layer) to "…and a read-only quality register
over the library." It stays within ADR-0008's boundaries: **read-only** — no tag
writing, no re-encoding, no library reorganization. *(Open question §8: this
positioning shift may warrant an ADR amendment.)*

## 3. Architecture

Two evidence objects, one sensor model:

```
existing_library_evidence  (measured from the on-disk library file)
candidate_import_evidence  (measured from the incoming candidate — already exists)
        │                                  │
        └──────────────┬───────────────────┘
                       ▼
         decision: candidate vs measured existing
```

Reuse the existing sensor results contract (ffprobe, `flac_t`, `flac_detective`,
`release_identity`, and later DR/loudness/AcoustID). The same `SensorResult`
shape and `evidence_schema_version` apply, so library evidence is queryable and
auditable exactly like import evidence.

### 3.1 Cost is the hard constraint — tiered scanning

FLAC Detective is the heaviest sensor (minutes/album). A full-library *eager*
spectral scan does not scale. The index is therefore **tiered**:

| Tier | Sensors | Cost | When |
|---|---|---|---|
| Cheap | ffprobe (codec, bitrate, sample rate, bit depth, channels) | sub-second/file | eager / on first sight |
| Integrity | `flac -t` | seconds/album | lazy or background-throttled |
| Spectral | FLAC Detective | minutes/album | **on-demand** (a candidate targets this album) or background-throttled, never full-library-eager |

### 3.2 Lead with on-demand, not a full batch

The import decision only needs measured evidence for the **album the candidate
targets**. Mintarr already fetches that album's trackfile paths from Lidarr, so
the smallest correct fix is: at import time, measure the existing files for
*that album* on demand, cache the result in the index, and compare. This closes
the correctness gap with no library-wide batch job. The **background full-library
index + ranking dashboard** is a superset that follows (slice 5+).

### 3.3 File-access contract (locked for slice 1)

Measuring existing files requires Mintarr to **read** the library; today it only
mounts `OUTPUT_BASE`. The contract:

| Env | Meaning |
|---|---|
| `MINTARR_LIBRARY_ROOT` | Mintarr's **read-only** mount of the Lidarr library root (unset ⇒ measurement off, label-only fallback) |
| `MINTARR_LIBRARY_LIDARR_ROOT` | Lidarr's view of that same root — the path prefix that appears in trackfile `path` |

**Mapping.** For a Lidarr trackfile `path`, strip the `MINTARR_LIBRARY_LIDARR_ROOT`
prefix and join the remainder onto `MINTARR_LIBRARY_ROOT`. A `path` that does not
start with the configured Lidarr root is **unmapped** (fallback, not an error).

**Containment + safety (reuse the restore/backup discipline).**

- Resolve the mapped path with `realpath` and require it to stay
  `is_relative_to(MINTARR_LIBRARY_ROOT)` — reject traversal and symlink escape.
- Reject symlinked files (or resolve and re-check containment); never follow a
  link out of the mount.
- Open **read-only**; never write/move/delete/rename inside the library.

**Fallback (never crash, never block).** If `MINTARR_LIBRARY_ROOT` is unset, the
path is unmapped/unresolvable/missing, or fails containment, that trackfile is
recorded as `unmeasured` with a reason and the album falls back to today's
Lidarr-label behaviour.

### 3.4 Storage + staleness

A new `library_evidence` table in `state_db`, keyed by Lidarr `trackfile_id`,
storing: album id, resolved path, `size`, `mtime`, the per-sensor results, the
measured **quality vector** (§4), `sensor_version`, and `measured_at`. Evidence
is **re-measured when `(path, size, mtime)` changes** (Lidarr replaced the file)
and invalidated when Lidarr reports the trackfile gone. `sensor_version` is
stored so historical measurements stay interpretable (same audit principle as
decisions).

## 4. Quality vector + precedence (not just "better kbps")

Quality is a **vector**, not a scalar bitrate. Each track's measured evidence
yields the dimensions below; comparison is **lexicographic by precedence**, so a
higher tier never excuses a failure on a more important axis:

| # | Axis | Source | Rule |
|---|---|---|---|
| 1 | **Identity** | F5.1 release identity | `WRONG_ALBUM` is disqualifying — quality can never override the wrong release (ADR-0013). |
| 2 | **Hard validity** | ffprobe + `flac -t` | A file that doesn't decode / fails integrity is unusable regardless of nominal format. |
| 3 | **Authenticity** | FLAC Detective | A measured-fake "FLAC" loses to a genuine one at the same nominal format. |
| 4 | **Lossless tier** | ffprobe codec / bit depth / sample rate | lossless > lossy; among lossless, higher bit depth / sample rate is better. |
| 5 | **Completeness** | Lidarr track stats | More complete is better; may override a *tier* gap (§5) since a complete release beats a partial one. |

Comparison: a candidate **replaces** the existing release only when it is at
least equal on every higher-precedence axis and strictly better on one, or it
resolves a defect the existing release has (invalid/fake/incomplete). Otherwise
the existing release is kept, or — when the comparison is genuinely close or
mixed — routed to `REVIEW_REQUIRED` so the operator keeps the veto. The result
maps onto the existing `ACCEPT` / `ACCEPT_PROVISIONAL` / `REVIEW_REQUIRED` /
`BLOCK` decisions and keeps ADR-0013 two-axis precedence.

### 4.1 Default-safe rollout

Gated by `MINTARR_MEASURED_EXISTING` (default **off** ⇒ today's label
behaviour), and only when measured existing evidence is available; otherwise it
falls back to the label path. So the change cannot regress decisions until opted
in, and an unmeasured/unmounted library behaves exactly as today.

## 5. Album / release rollup

Evidence is stored per `trackfile_id`, but the import decision is at
**album/release** level. Roll the per-track vectors up as follows:

- **Validity:** the album is valid only if **every present track** passes hard
  validity; any invalid track is an album-level integrity defect (a candidate
  that fixes it can win).
- **Authenticity:** album authenticity = the **worst** track (one fake track
  taints the release's authenticity claim) — but per-track evidence is retained,
  and "one bad track" surfaces the release as `SUSPICIOUS` → `REVIEW_REQUIRED`,
  never a silent accept.
- **Lossless tier:** album tier = the **minimum** tier across tracks; a
  mixed-quality album is explicitly flagged (not averaged into looking better
  than its weakest track).
- **Completeness:** present vs `expected_track_count` (Lidarr); multi-disc uses
  Lidarr's aggregate track counts across discs.
- **"One bad track" rule:** an otherwise-equal candidate that fixes a single
  invalid/fake/missing track in the existing release wins; a candidate that
  *introduces* a single fake/invalid track among good ones → `REVIEW_REQUIRED`.

Per-track replacement (swapping one file) is **out of scope for v1** — Mintarr
decides at the release granularity it already imports at.

## 6. Dashboard visibility

Surface `existing_library_evidence` in the record drawer (and later a library
view): the operator must see *why* Mintarr judges the existing file good/bad —
measured codec/bit depth/sample rate/spectral verdict, not a bare label.

## 7. Non-goals

- No tag writing, no re-encoding, no library reorganization — read-only
  ([ADR-0008](../architecture/adr/0008-strategic-positioning.md) boundary).
- No replacing Lidarr as identity/ownership truth.
- Not a general music-analysis service; evidence exists to inform Mintarr
  decisions and operator review.
- No full-library eager spectral scan.

## 8. Implementation slices

1. **On-demand existing-album measurement (pure + cached).** Resolve the target
   album's trackfile paths (Lidarr) → Mintarr mount; measure with ffprobe (+
   `flac -t`); store in `library_evidence`. Graceful degrade if unmounted. **No
   decision change** — evidence recorded only.
2. **Dashboard visibility.** Show measured existing evidence in the record drawer.
3. **Decision uses measured existing (flag-gated).** `MINTARR_MEASURED_EXISTING`
   default-off: compare candidate vs measured existing, incl. lossless tiers.
4. **Spectral tier on-demand.** Add FLAC Detective to the existing-album
   measurement (throttled) so measured-fake existing FLAC is detectable.
5. **Background full-library index + ranking.** Tiered, throttled scan of the
   whole library; library quality view; re-scan on change. (Largest slice.)

## 9. Decisions taken & open questions

- **ADR-0008 amendment — decided:** no full ADR is needed before slices 1–2
  (read-only measurement + visibility change nothing). Before **slice 3** (when
  measured evidence changes decisions) we land a short ADR-0008 amendment stating
  that Mintarr may hold **read-only quality evidence over Lidarr-owned files but
  does not own library management**.
- **Mount contract — locked** in §3.3 (`MINTARR_LIBRARY_ROOT` +
  `MINTARR_LIBRARY_LIDARR_ROOT`, realpath containment, symlink rejection,
  read-only, `unmeasured` fallback). Partial reachability degrades per-trackfile.
- **Quality vector + rollup — locked** in §4–§5.
- **Open:** background-scan triggers (on connect? scheduled? operator-initiated?)
  and the throttle/budget so the spectral tier never starves the import worker —
  deferred to slice 5.
