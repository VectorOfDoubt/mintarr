# F3.5a - Soulseek Completed-Folder Ingest

> **Type:** Design document
> **Version:** 0.1 - 2026-06-01
> **Status:** Implemented
> **Related:** [ADAPTER_PROTOCOL_v1.md](../specs/ADAPTER_PROTOCOL_v1.md), [CONNECTOR_MANIFEST_v1.md](../specs/CONNECTOR_MANIFEST_v1.md), [F4.3_CONNECTOR_CONFIG_DRY_RUN.md](F4.3_CONNECTOR_CONFIG_DRY_RUN.md)

## 1. Goal

F3.5a adds the first Soulseek source without depending on slskd HTTP search/download.

Operators can point Mintarr at a mounted slskd completed-download root and manually enqueue a completed folder. Mintarr copies the files into its work area, runs the same normalize/verify/import pipeline as TIDAL and LocalFolder, and leaves Soulseek source files untouched.

## 2. Non-Goals

- No slskd HTTP search.
- No slskd download trigger.
- No peer/user metadata scraping.
- No source-aware verification thresholds. Soulseek still uses the existing hard gates and FLAC Detective policy.
- No source deletion or consume markers.

## 3. Configuration

| Env var | Default | Meaning |
|---|---|---|
| `SOULSEEK_ENABLED` | `false` | Master toggle for the adapter. |
| `SOULSEEK_DOWNLOAD_ROOT` | unset | Mounted slskd completed-download root. |
| `SOULSEEK_MAX_FILES` | `300` | Maximum files in a candidate folder. |
| `SOULSEEK_MAX_BYTES` | `0` | Maximum total bytes, with `0` meaning unlimited. |
| `SOULSEEK_SETTLE_SECONDS` | `10` | Seconds a folder must remain size-stable before ingest. |
| `SOULSEEK_SEARCH_ENABLED` | `false` | Reserved for F3.5b; F3.5a search returns `[]`. |

The adapter is enabled only when `SOULSEEK_ENABLED=true` and `SOULSEEK_DOWNLOAD_ROOT` exists as a directory.

## 4. Source ID

`source_id` is a normalized POSIX relative path inside `SOULSEEK_DOWNLOAD_ROOT`, matching LocalFolder's path contract.

Example:

```text
soulseek:Artist/Album
```

The adapter blocks:

- absolute paths
- `..` traversal
- symlinked path components
- symlinked nested files
- paths resolving outside `SOULSEEK_DOWNLOAD_ROOT`

## 5. Completed-Folder Validation

Before enqueue and again during worker copy, the folder must pass completed-folder checks:

1. No partial marker files.
2. File count is at or below `SOULSEEK_MAX_FILES`.
3. Total bytes are at or below `SOULSEEK_MAX_BYTES` when non-zero.
4. File size/mtime snapshot is unchanged after `SOULSEEK_SETTLE_SECONDS`.
5. At least one supported audio file exists.

Partial marker suffixes include `.part`, `.partial`, `.tmp`, `.download`, `.crdownload`, and `.incomplete`.

## 6. HTTP API

Add:

```text
POST /soulseek/ingest
```

Request:

```json
{"path": "Artist/Album"}
```

Response:

```json
{
  "status": true,
  "nzo_ids": ["<jid>"],
  "job_id": 123
}
```

Invalid paths return `400`. Not-yet-settled folders return `409`. Disabled adapter/config returns `503`.

## 7. Connector

Register a source connector:

- id: `soulseek`
- kind: `source`
- adapter: `adapters.soulseek:SoulseekCompletedAdapter`
- default_enabled: `false`
- docker_service: `slskd`
- required_env: `SOULSEEK_ENABLED`, `SOULSEEK_DOWNLOAD_ROOT`
- optional_env: `SOULSEEK_MAX_FILES`, `SOULSEEK_MAX_BYTES`, `SOULSEEK_SETTLE_SECONDS`, `SOULSEEK_SEARCH_ENABLED`
- capabilities: `completed_folder_ingest`, `copy_source_files`, `manual_enqueue`

F4.3 mode controls apply normally. A Soulseek source in `dry_run` can show health/config but cannot enqueue imports.

## 8. Tests

Implementation should cover:

- disabled/enabled conditions
- path traversal and symlink blocking
- partial marker rejection
- max files / max bytes rejection
- settle-window rejection
- happy-path copy leaves source untouched
- `/soulseek/ingest` enqueue/dedupe behavior
- connector manifest and F4.3 mode gate behavior

Implemented coverage lives in `tests/test_soulseek_adapter.py`.
