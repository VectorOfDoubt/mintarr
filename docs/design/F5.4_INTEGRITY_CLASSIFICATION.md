# F5.4 — Integrity classification (MD5 mismatch vs hard decode error)

> **Type:** Design
> **Status:** Accepted
> **Owner:** Mintarr maintainers
> **Related:** [F5.4 library evidence index](F5.4_LIBRARY_EVIDENCE_INDEX.md), [ADR-0008 strategic positioning](../architecture/adr/0008-strategic-positioning.md)

## 1. Problem (found in dogfood)

The first at-scale library scan (≈46k trackfiles) put **79 albums** into the
`invalid` bucket. Investigation showed they are **not corrupt**: the FLAC files
have a valid `fLaC` marker, a non-zero STREAMINFO MD5, full length, and they
**decode cleanly** end-to-end (verified with `ffmpeg -f null` on three files
across unrelated artists — Eurythmics, Faith No More, Five For Fighting). They
fail `flac -t` only on an **MD5 signature mismatch**: the audio was re-tagged or
re-processed after encoding without recomputing the FLAC MD5. Every track of
each album fails uniformly, which is the signature of a processing class, not
random bitrot.

Today `app/library_evidence.py:_default_prober` collapses both cases into one
bit: `integrity_ok = (flac -t returncode == 0)`. So an MD5 mismatch is recorded
identically to genuine decode corruption. Via the rollup, `existing.any_invalid`
is True, and `library_comparison.compare()` returns `UPGRADE`. **If
`MINTARR_MEASURED_EXISTING` were enabled, Mintarr would recommend re-downloading
79+ albums of perfectly playable music** purely because their MD5 is stale —
the opposite of "quality truth."

## 2. Decision

Split the FLAC integrity signal into two independent dimensions:

| Dimension | Meaning | `flac -t` evidence |
|---|---|---|
| **Decode validity** (`integrity_ok`) | The audio frames decode; the file is usable | non-zero **only** on real decode/frame errors |
| **Checksum verification** (`checksum_ok`) | The decoded audio matches the stored STREAMINFO MD5 | `False` on `MD5 signature mismatch`; `True` when verified; `None` when not applicable/unchecked |

An **MD5 mismatch becomes `integrity_ok=True, checksum_ok=False`** — the file is
valid, usable audio with a stale checksum. A **hard decode error stays
`integrity_ok=False`** (genuine corruption), exactly as today.

### 2.1 Distinguishing the two from `flac -t`

`flac -t` returns non-zero for both, so classify by stderr:

- stderr contains **`MD5 signature mismatch`** (case-insensitive) and shows no
  decode/frame error → **checksum mismatch** (`integrity_ok=True`,
  `checksum_ok=False`).
- any other non-zero result (decode errors, frame CRC errors, truncation,
  unreadable) → **hard error** (`integrity_ok=False`). This is the
  **conservative default**: an unrecognized `flac -t` failure is treated as
  invalid, never softened.
- returncode 0 → `integrity_ok=True`, `checksum_ok=True` (flac verified the MD5;
  an *unset* STREAMINFO MD5 also exits 0 and is reported `checksum_ok=None`,
  since nothing was checked — see §3).

Non-FLAC codecs (where `flac -t` does not run) keep `checksum_ok=None`.

## 3. Data model

`TrackMeasurement` (in `library_evidence.py`) gains `checksum_ok: bool | None`.
`library_evidence` gains a nullable `checksum_ok INTEGER` column (idempotent
migration, same pattern as the spectral columns). Old rows read `NULL` until
re-measured.

`SENSOR_VERSION` is **bumped**: the meaning of `integrity_ok` changes (MD5
mismatch flips `False → True`), so every stored row must be re-measured under the
new semantics. The existing freshness guard (`is_measured_row_fresh`,
sensor-version match) makes the next scan re-measure all rows automatically; no
backfill script is needed.

## 4. Rollup + comparison

`AlbumQuality` (in `library_comparison.py`) gains `any_md5_mismatch: bool` (any
fresh measured track with `checksum_ok is False`). `album_quality` keeps
`any_invalid` meaning **decode-invalid only** (now strictly genuine corruption).

`compare()` is **unchanged in behaviour** and deliberately does **not** act on
`any_md5_mismatch`: a stale checksum is not a quality defect and must never
drive an `UPGRADE` or a block. The whole point is that a playable file with a
stale MD5 is not a reason to replace it. MD5 mismatch is **advisory only** —
surfaced in the ranking, invisible to the decision. (Because MD5-mismatch rows
are now `integrity_ok=True`, they simply stop forcing `any_invalid`; no new
branch is added to `compare()`.)

## 5. Ranking view

Add a `checksum_mismatch` bucket to the library-quality ranking. Worst-first
precedence (it is a real finding — the file was modified post-encode — but softer
than corruption or a measured fake, and not a playback problem):

```
invalid → measured_fake → checksum_mismatch → stale → unmeasured
→ lossy → redbook → mixed_tier → unknown_authenticity → ok
```

Label/description make the distinction explicit: "Plays fine; stored FLAC MD5 no
longer matches the audio (re-tagged/re-encoded after ripping). Not corruption."
The ranking is DB-only (no live stat, per the slice-5d contract); the new bucket
derives from the stored `checksum_ok` column.

## 6. Default-safety & scope

- Scoped to `library_evidence` measurement of **existing** files. The import
  candidate's hard gates are unchanged.
- No decision changes when `MINTARR_MEASURED_EXISTING` is off (default).
- Conservative: only an explicit `MD5 signature mismatch` is softened; every
  other `flac -t` failure stays `invalid`.
- Read-only throughout; no file is modified, and Mintarr never rewrites a FLAC
  MD5 (that would be library management, outside ADR-0008).

## 7. Test plan

- Prober classification (injected fake `flac -t` results): clean → ok/checksum_ok
  True; `MD5 signature mismatch` → integrity_ok True + checksum_ok False; decode
  error → integrity_ok False; unset-MD5 (rc 0) → checksum_ok None; non-FLAC →
  checksum_ok None.
- Storage round-trip of `checksum_ok` (incl. the migration on a pre-existing DB).
- `album_quality`: `any_md5_mismatch` set from a fresh checksum-mismatch row;
  `any_invalid` **not** set by a checksum mismatch.
- `compare()`: a candidate vs an existing album whose only defect is an MD5
  mismatch does **not** return `UPGRADE` on that basis (no auto-replace of
  playable files).
- Ranking: a checksum-mismatch album lands in the `checksum_mismatch` bucket, not
  `invalid` and not `ok`; precedence respected.

## 8. Non-goals

- No FLAC re-encoding or MD5 rewriting (Mintarr stays read-only over the library).
- No change to spectral authenticity, tiers, or completeness.
- No new env flag — this is a correctness fix to existing measurement, on by
  default for the measurement/ranking; it only reaches a decision when the
  existing `MINTARR_MEASURED_EXISTING` opt-in is enabled.
