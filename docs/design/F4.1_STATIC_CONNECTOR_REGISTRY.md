## 1. Why F4.1 happens first

ADR-0003 locks the connector/adapter split, and the connector architecture document captures the full F4 plan. F4.1 is the smallest implementable slice of that plan: a static registry of connectors, manifests for existing integrations, and a single `GET /dashboard/v1/connectors` endpoint that returns them.

This is the foundation everything else in F4 builds on:

- **F4.2 Integrations dashboard tab** needs the registry to know what to render
- **F4.3 enable/disable + dry-run** needs the registry to know what connectors exist before persisting per-connector config
- **F4.4 install guidance** needs the registry's `install_profile` / `docker_service` hints
- **F3.5a Soulseek connector** registers itself in the registry

Without F4.1 first, each of these would re-invent the connector concept slightly differently and we would carry the rework cost forever.

## 2. Goals / non-goals

### Goals

- Define the `ConnectorManifest` dataclass and serialised JSON schema
- Define the runtime `Connector` wrapper class
- Implement the connector registry under `app/connectors/`
- Author manifests for all existing integrations: `tidal`, `local_folder`, `ffprobe`, `flac_t`, `flac_detective`, `lidarr_manual_import`, `lidarr_rescue_rescan`
- Add `GET /dashboard/v1/connectors` returning the list with runtime status
- Tests for manifest shape, registry registration / lookup, required-connector enforcement

### Non-goals

- UI for the Integrations tab (F4.2)
- `connector_config` table or enable/disable mechanics (F4.3)
- Compose profile / install guidance display (F4.4)
- Beets/Picard/AcoustID or CUETools/CTDB connectors (F4.5)
- Dynamic plugin loading (deferred per ADR-0003 §"Static-first")
- Connector health polling architecture (Phase 3 observability work; F4.1 returns whatever sync health check returns)

## 3. Adapter vs Connector boundary in code

Per ADR-0003, the boundary is:

- Adapter code lives under `app/adapters/`
- Connector code lives under `app/connectors/`
- A connector either wraps an adapter (e.g., `TidalConnector` references `TidalAdapter`) or stands alone (e.g., `FfprobeConnector` has no adapter)

The registry holds connectors, not adapters. Existing adapter-only consumers (the pipeline, the worker, the addurl dispatcher) keep using `adapters.get_adapter(...)`. They are unaffected by F4.1.

## 4. ConnectorManifest dataclass

```python
# app/connectors/base.py

from dataclasses import dataclass, field
from enum import Enum


class ConnectorKind(str, Enum):
    SOURCE = "source"
    VERIFIER = "verifier"
    OUTPUT = "output"


class ConnectorMode(str, Enum):
    DISABLED = "disabled"
    DRY_RUN = "dry_run"
    IMPORT = "import"


@dataclass(frozen=True)
class ConnectorManifest:
    """Static metadata describing a connector. Loaded at boot, immutable
    for the life of the container. The fields here are exactly the fields
    serialised in GET /dashboard/v1/connectors responses (under "manifest").
    """
    id: str                              # "tidal", "flac_detective", "lidarr_manual_import"
    display_name: str                    # "TIDAL", "FLAC Detective"
    kind: ConnectorKind                  # source / verifier / output
    api_version: str                     # "1.0.0" — per ADR-0004
    adapter_class: str | None            # qualified name, e.g. "adapters.tidal:TidalAdapter"
    default_enabled: bool
    required: bool                       # ffprobe and flac_t for import-mode sources
    install_profile: str | None          # compose profile hint, e.g., "soulseek"
    docker_service: str | None           # expected service name, e.g., "slskd"
    required_env: tuple[str, ...]        # env vars that must be set
    optional_env: tuple[str, ...]
    capabilities: tuple[str, ...]        # e.g. ("spectral_analysis", "fake_lossless_verdict")
    docs_url: str                        # relative path or full URL
    min_supported_version: str | None    # SemVer string for external service version
```

### Runtime status JSON shape

`GET /dashboard/v1/connectors` returns:

```json
{
  "api_version": "1.0.0",
  "connectors": [
    {
      "id": "tidal",
      "kind": "source",
      "display_name": "TIDAL",
      "manifest": {
        "...": "(verbatim manifest fields)"
      },
      "runtime": {
        "installed": true,
        "enabled": true,
        "mode": "import",
        "health": "ok",
        "version": null,
        "last_error": null,
        "last_checked_at": "2026-05-26T18:30:00Z"
      }
    }
  ]
}
```

The serialisation is stable per `api_version`. Breaking changes require bumping `api_version` and producing `CONNECTOR_MANIFEST_v2.md` per ADR-0004.

## 5. Connector class

```python
# app/connectors/base.py (continued)

from typing import Protocol


class Connector(Protocol):
    """Runtime wrapper that pairs a manifest with health/version detection.
    Connectors are registered statically at boot; the registry holds the
    Connector instances, not the manifests in isolation.
    """
    manifest: ConnectorManifest

    def is_installed(self) -> bool:
        """Returns True if the underlying tool/service is available.
        For adapter-backed connectors, defers to the adapter.is_enabled().
        For verifier connectors, checks for binary / HTTP endpoint."""
        ...

    def is_enabled(self) -> bool:
        """Returns True if the operator has not disabled this connector.
        F4.1 returns manifest.default_enabled. F4.3 reads from
        connector_config table."""
        ...

    def health(self) -> ConnectorHealth:
        """Synchronous health check. F4.1 returns a basic enum + optional
        error message. Caching, scheduling, and background polling are
        Phase 3 observability work."""
        ...

    def detected_version(self) -> str | None:
        """Returns the detected version of the underlying tool/service.
        Cheap probes only — `ffprobe --version`, `GET /api/health`, etc."""
        ...
```

`ConnectorHealth` is:

```python
@dataclass(frozen=True)
class ConnectorHealth:
    status: str               # "ok" | "degraded" | "blocked" | "missing" | "disabled"
    last_error: str | None    # short description if status != "ok"
    last_checked_at: float    # unix timestamp
```

## 6. Registry

```python
# app/connectors/registry.py

_connectors: dict[str, Connector] = {}


def register(connector: Connector) -> None:
    """Idempotent registration. Boot-time only."""
    if connector.manifest.id in _connectors:
        raise ValueError(f"Connector '{connector.manifest.id}' already registered")
    _connectors[connector.manifest.id] = connector


def get_connector(connector_id: str) -> Connector | None:
    return _connectors.get(connector_id)


def all_connectors() -> list[Connector]:
    return list(_connectors.values())


def required_connectors() -> list[Connector]:
    return [c for c in _connectors.values() if c.manifest.required]


def reset_registry() -> None:
    """Test-only helper."""
    _connectors.clear()
```

Registration happens in `app/server.py` boot, after the adapter registry is populated. Order matters: `LidarrManualImportConnector` references `LIDARR_API_URL` env which is read at registration time; `TidalConnector` references `TidalAdapter` which must be registered first.

## 7. Initial connector set

| ID | Kind | Adapter? | Required | Notes |
|---|---|---|---|---|
| `tidal` | source | `TidalAdapter` | false | Enabled if token.json present |
| `local_folder` | source | `LocalFolderAdapter` | false | Enabled if `LOCAL_INGEST_PATH` mount valid |
| `ffprobe` | verifier | none | true | Required for any source in import mode |
| `flac_t` | verifier | none | true | Required for FLAC integrity gate |
| `flac_detective` | verifier | none | true | Required for spectral heuristic |
| `lidarr_manual_import` | output | none | false (output, see invariant 8 below) | Default output target |
| `lidarr_rescue_rescan` | output | none | false | Fallback output target |

`F3.5a Soulseek` and future source connectors register themselves on top of this base set.

### Invariants enforced by the registry

1. **Required-connector check at boot.** If a `manifest.required = true` connector reports `installed = false`, Mintarr logs a warning and surfaces it on the dashboard. Boot does not fail — operators may run Mintarr in a partial state during installation.
2. **Source connectors in import mode require all required verifiers.** F4.3 enforces this when implementing enable/disable. F4.1 records the invariant as a check function but does not enforce mutation.
3. **Output connectors are not "required" individually.** At least one output connector must be installed for import-mode source connectors to function. This is asserted at the registry level (F4.1) and surfaced in dashboard (F4.2).

## 8. HTTP endpoint

```python
# app/server.py (new route)

@app.route("/dashboard/v1/connectors", methods=["GET"])
@require_apikey
def list_connectors():
    import connectors

    payload = {
        "api_version": "1.0.0",
        "connectors": [
            _serialize_connector(c) for c in connectors.all_connectors()
        ],
    }
    return jsonify(payload)


def _serialize_connector(c) -> dict:
    health = c.health()
    return {
        "id": c.manifest.id,
        "kind": c.manifest.kind.value,
        "display_name": c.manifest.display_name,
        "manifest": _serialize_manifest(c.manifest),
        "runtime": {
            "installed": c.is_installed(),
            "enabled": c.is_enabled(),
            "mode": "import" if c.is_enabled() else "disabled",
            "health": health.status,
            "version": c.detected_version(),
            "last_error": health.last_error,
            "last_checked_at": health.last_checked_at,
        },
    }
```

The endpoint is read-only in F4.1. Mutation endpoints (enable/disable/healthcheck) are F4.3.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Connector init order matters for boot reliability | Document required order; tests cover each connector independently |
| Health probes during boot slow down container start | F4.1 health is lazy — probes only run on first dashboard request; cached for 60s |
| `subprocess`-based version detection adds latency | Cache detected version for container lifetime; only re-probe on explicit `/healthcheck` POST (F4.3) |
| Connector manifests drift from underlying code | Tests check manifest invariants per connector |
| Adapter-backed connectors duplicate adapter logic | Connector defers to adapter for `is_installed()` and `is_enabled()` — single source of truth |

## 12. Open questions for review

1. **Should the `lidarr_*` connectors merge into one `lidarr_output` connector with two modes (`manual_import`, `rescue_rescan`), or stay as two distinct connectors?** Codex's original architecture document treated them as separate. Pro: clearer audit trail. Con: confusing UI (operator sees two Lidarr connectors).

2. **Should connectors implement `is_installed()` vs `is_enabled()` as separate methods, or collapse to one?** Current design has both. `installed` is "tool exists on disk"; `enabled` is "operator hasn't turned it off". F4.3 work needs both. F4.1 could collapse if the distinction is unused.

3. **Should `detected_version()` be eager (probed at boot) or lazy (probed on first request)?** Current design is lazy with 60s cache. Lazy avoids boot latency; eager avoids first-request latency.

4. **Should the registry support multiple connectors with the same `adapter_class`?** Imaginable scenario: two TIDAL accounts (work + personal) modelled as `tidal_primary` + `tidal_secondary`. Current design forbids it; the same adapter cannot back two connectors. Locked decision needed.

5. **Should the F4.1 endpoint be `/dashboard/v1/connectors` or `/api/v1/connectors`?** ADR-0004 puts versioned APIs under `/api/v1/`. Dashboard-specific endpoints under `/dashboard/v1/`. F4.1 is dashboard-facing; sticking with `/dashboard/v1/` for now. If non-dashboard clients want connector data, this can be re-exposed under `/api/v1/`.

## 13. What F4.1 does not change

- `app/adapters/` is untouched. Existing adapters continue to work without manifests.
- `app/pipeline.py` is untouched. The pipeline does not consult the connector registry.
- `app/server.py` is touched only to add the new endpoint and boot registration. Existing routes are untouched.
- `state_db` schema is untouched. F4.3 will add the `connector_config` table.
- Sidecar format is untouched.
