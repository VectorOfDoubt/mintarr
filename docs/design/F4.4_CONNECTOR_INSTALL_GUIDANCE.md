# F4.4 - Connector Install Guidance

> **Type:** Design document
> **Version:** 1.0 - 2026-06-03
> **Status:** Implemented - connector API guidance payload, dashboard guidance block, and operator docs
> **Related:** [F4.1 Static Connector Registry](F4.1_STATIC_CONNECTOR_REGISTRY.md), [F4.2 Integrations Dashboard](F4.2_INTEGRATIONS_DASHBOARD.md), [F4.3 Connector Config And Dry-Run](F4.3_CONNECTOR_CONFIG_DRY_RUN.md), [CONNECTOR_MANIFEST_v1.md](../specs/CONNECTOR_MANIFEST_v1.md)

## 1. Goal

F4.4 turns existing connector manifest hints into actionable setup guidance.
Operators should not have to infer why a connector is missing from raw fields
alone.

The Integrations dashboard should answer:

- Which required env var names apply?
- Which Docker service should be running?
- Which Compose profile should be enabled?
- Which docs link explains setup?
- Is the connector disabled, missing, or blocked?

## 2. Non-goals

- No app-managed Docker installation or updates.
- No Docker socket mount.
- No Compose file mutation from Mintarr.
- No dynamic plugin loading.
- No Phase 2 dashboard redesign.
- No secret display.

## 3. API Shape

Each connector returned by `GET /dashboard/v1/connectors` includes:

```json
{
  "install_guidance": {
    "show": true,
    "reason": "Dependency is missing or not reachable.",
    "actions": [
      "Enable the `soulseek` compose profile.",
      "Verify the `slskd` service is running.",
      "Configure required environment variable names: `SOULSEEK_ENABLED`, `SOULSEEK_DOWNLOAD_ROOT`."
    ],
    "required_env": ["SOULSEEK_ENABLED", "SOULSEEK_DOWNLOAD_ROOT"],
    "optional_env": ["SLSKD_API_KEY"],
    "docker_service": "slskd",
    "install_profile": "soulseek",
    "docs_url": "connectors/soulseek/",
    "min_supported_version": null
  }
}
```

The payload is deliberately secret-safe. It may include names and hints, never
values, tokens, API keys, local private host paths, or Docker-socket data.

## 4. Dashboard Behavior

The Integrations card renders a compact guidance block when
`install_guidance.show=true`.

Triggers include:

- `runtime.health` is `missing`, `blocked`, or `disabled`
- `runtime.installed=false`
- `runtime.enabled=false`
- `runtime.mode=disabled`

Ready connectors still include `install_guidance`, but with `show=false`, so API
consumers can rely on a stable shape.

## 5. Operator Docs

`docs/operations/CONFIGURATION.md` documents how to use the guidance:

- check required env names and mounts first
- verify declared Docker service reachability
- enable declared Compose profiles before switching to import mode
- keep optional connectors in dry-run until evidence is trusted
- never mount the Docker socket into Mintarr

## 6. Tests

Implemented tests cover:

- guidance payload exists on connector registry responses
- missing connectors produce service/profile/env action text
- payload does not expose secret values
- dashboard shell contains the guidance rendering path
- docs links still build
